# 30 ідей комунікації Людина↔Odoo: Критичний аналіз

**Версія:** 1.0.1
**Дата:** 2026-01-28
**Статус:** Для обдумування

---

## Контекст

Аналіз 30 ідей покращення комунікації людина↔Odoo через конектор ПЛМ (Протокол Літаючого Маховика).

**Критерії оцінки:**
1. **Механіка** — як працює на рівні коду та користувача
2. **Сприйняття** — чи зрозуміє користувач, чи не дратуватиме
3. **Вартість** — чи варта реалізація зусиль
4. **Ризик** — чи може зламати те, що працює

## 🛡️ НАДІЙНІСТЬ

### Ідея 1: Діалоги підтвердження з контекстом

**Опис:** Операції-шлагбауми показують повний контекст: що змінюється, хто ініціював, які наслідки. ШІ генерує зрозумілий опис.

**Механіка:**
- Код: Тригер шлагбауму → отримання контексту → резюме від ШІ → показ діалогу
- Користувач: Натискає "Затвердити" → бачить модальне вікно з описом → підтверджує

**Сприйняття:**
- ✅ Досвідчені користувачі оцінять контекст
- ⚠️ Якщо на КОЖНУ дію — дратуватиме
- ⚠️ Резюме від ШІ може бути неточним

**Вартість:** СЕРЕДНЯ
**Ризик:** Галюцинації ШІ у критичному контексті

**Вердикт: 🟡 УМОВНО — тільки для критичних операцій (затвердження CAPA, фазовий контроль)**

### Ідея 2: Вікно скасування для критичних операцій

**Опис:** Після виконання операції — 5-хвилинне вікно для скасування.

**Механіка:**
- Код: Операція → м'яке виконання → таймер 5 хв → остаточне збереження АБО відкат
- Користувач: Сповіщення "Виконано. Скасувати протягом 5 хв"

**Сприйняття:**
- ✅ Скасування як у пошті — знайомий підхід
- ⚠️ Закрив браузер — втрачено можливість скасувати?
- ⚠️ Інші користувачі бачать "виконано" чи "очікує"?

**Вартість:** ВИСОКА (проміжна таблиця, ізоляція транзакцій)
**Ризик:** Конкурентні помилки, проблеми з відповідністю для ПАТ

**Вердикт: 🔴 НЕ РЕКОМЕНДУЮ — занадто складно**

### Ідея 3: Виявлення аномалій у введених даних

**Сприйняття:**
- ✅ Запобігає друкарській помилці (85 замість 8.5)
- ✅ Не блокує, тільки попереджає

**Вартість:** НИЗЬКА (прості статистики)
**Ризик:** Мінімальний

**Вердикт: 🟢 РЕКОМЕНДУЮ — простий варіант (±3σ) з першого дня**
